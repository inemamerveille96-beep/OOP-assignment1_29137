This guide maps the questions in [`assign.mdx`](./assign.mdx) to the source files that address them. It is an orientation guide, not a replacement for the runnable Java project.

**Coverage key**

- **Implemented:** the main requested feature is present in the source.
- **Partial:** the basic feature exists, but one or more details in the assignment are not implemented yet.

## How the main OOP concepts are demonstrated

- **Encapsulation:** domain state is held in private fields and accessed through getters/setters.
- **Inheritance:** `Student` and `Teacher` inherit academic-member state; `Administrator` inherits person state.
- **Abstraction:** `Person` and `AcademicMember` define shared state and abstract role/category behavior.
- **Interfaces:** entities implement `Identifiable` and `Registrable`; the menu uses interface types in its polymorphism example.
- **Runtime polymorphism:** `demonstratePolymorphism()` calls overridden person behavior through `Person` references.
- **Object relationships:** courses refer to departments and teachers; enrollments refer to students and courses; loans refer to students and books.
- **Validation and exceptions:** each model validates its own key constraints, while the menu catches business exceptions and displays a message.

## Suggested demonstration

1. Compile from the project root:

   ```text
   javac -d out (Get-ChildItem -Recurse -Filter *.java | % { $_.FullName })
   ```

2. Run the menu:

   ```text
   java -cp out com.auca.main.Main
   ```

3. Register a Department, then create a Student and Teacher using that Department.
4. Create a Course, enroll a Student, then record an Assessment and Fee Payment.
5. Register a Library Book, borrow it, and return it to observe available-copy changes.
6. Use View All Records, Search by ID, Student Academic Summary, Payment History, and Demonstrate Polymorphism.

The in-memory collections reset when the program exits. To meet every detail of the practical smart-form specification, the partial workflows identified above would need to be extended.
